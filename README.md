## 📁 Repository Structure

Solutions are stored using the LeetCode problem number followed by the problem title.

```text
Leetcode-Solutions/
│
├── <problem-number>-<problem-title>.cpp
├── <problem-number>-<problem-title>.java
├── <problem-number>-<problem-title>.sql
│
├── README.md
│
└── .github/
    └── workflows/
        └── update-leetcode-stats.yml
```

### 📌 Naming Convention

The recommended format is:

```text
<Problem Number>-<Problem Title>.<extension>
```

The workflow also accepts a `.` or whitespace after the problem number.

Examples:

```text
1234-Problem Title.cpp
1234.Problem Title.java
1234 Problem Title.sql
```

The **problem number must be present at the beginning of the filename** so the automation can identify it.

## 🤖 Automatic Statistics

This repository uses **GitHub Actions** to maintain the statistics automatically.

Whenever a new solution is pushed, the workflow:

```text
        New Solution
              │
              ▼
        GitHub Push
              │
              ▼
      Scan Solution Files
              │
              ▼
    Extract LeetCode IDs
              │
              ▼
    Fetch LeetCode Difficulty
              │
       ┌──────┼──────┐
       ▼      ▼      ▼
    🟢 Easy 🟡 Medium 🔴 Hard
       │      │      │
       └──────┼──────┘
              ▼
       Count Problems
              │
              ▼
       Update README
              │
              ▼
      Commit Automatically
```

### ✨ No Manual Updating

You do **not** need to manually update:

* Total problems
* Easy problems
* Medium problems
* Hard problems
* Progress statistics

Simply add your solution and push it.

## 🤝 For Fellow Learners

If you're learning DSA, feel free to use this repository as a reference.

However, try not to immediately copy a solution.

A better process is:

```text
1️⃣ Read the problem
2️⃣ Understand the examples
3️⃣ Think of a brute-force approach
4️⃣ Try to optimize it
5️⃣ Implement your own solution
6️⃣ Test edge cases
7️⃣ Study the optimal approach if stuck
8️⃣ Re-implement it without looking
```

The real skill isn't remembering the code.

It's recognizing **the pattern behind the code**.
